# 02. ПРОДУКТОВАЯ ФИЛОСОФИЯ

SuperApp — интеллектуальная рабочая система риэлтора, которая помогает не упускать клиентов, находить подходящие объекты и доводить рабочие возможности до сделок.

Долгосрочная концепция — **«смартфон для бизнеса»**.

Пользователь получает единую базовую платформу и самостоятельно подключает нужные профессиональные модули.

Основные модули экосистемы:

1. Unified CRM Inbox.
2. Lead Shield.
3. AI Client Rescue.
4. Client 360°.
5. Property Hub.
6. Smart Match.
7. Showing Manager.
8. Deal Management.
9. Commission Tracking.
10. AI Copilot.
11. Agency Management.
12. Analytics.

В будущем подключаются дополнительные инструменты привлечения клиентов, работы с собственниками, публикации объектов, межагентского сотрудничества и профессиональной аналитики.

Но **Today остаётся единым главным экраном всей системы**.

Сегодня он показывает обращения, звонки и задачи.

Когда пользователь подключит Smart Match — здесь появятся подходящие сочетания клиентов и объектов.

Когда подключит показы — здесь появятся подтверждения встреч.

Когда подключит сделки — здесь появятся важные шаги сделок.

Новые модули расширяют содержимое Today, но не превращают его в перегруженную панель управления.

# 03. ГЛАВНАЯ ЦЕЛЬ TODAY

Пользователь открывает приложение и за 3–5 секунд должен получить ответы:

**1. Что произошло, пока меня не было?**

Новые обращения, пропущенные звонки, новые сообщения из доступных подключённых источников.

**2. Кому я ещё должен ответить?**

Обращения без зафиксированного ответа, с учётом возможностей источника.

**3. Что я обещал клиентам?**

Назначенные обратные звонки, отправка подборок, подтверждение показов.

**4. Что требует внимания именно сейчас?**

Просроченные действия и срочные рабочие задачи.

**5. Что мне сделать следующим?**

Конкретное действие: позвонить, подготовить ответ, открыть клиента, подтвердить показ или закрыть задачу.

Главное эмоциональное ощущение:

**«Я контролирую свой рабочий день. Мне не нужно помнить всё самому».**

Today — не отчёт для директора.

Это прежде всего **ежедневный помощник самого риэлтора**.

# 04. ОСНОВНОЙ UX-ПРИНЦИП

## Action-First, Not Dashboard-First

Не начинай экран с огромных аналитических графиков, декоративных показателей и сложных CRM-воронок.

Приоритет визуальной иерархии:

**Первое:** что необходимо сделать.

**Второе:** почему это важно.

**Третье:** как выполнить действие.

**Четвёртое:** что уже выполнено.

**Пятое:** общая статистика, если она действительно помогает.

Пользователь не должен открывать пять разделов, чтобы понять, кому перезвонить.

На Today конкретное действие должно быть видно сразу.

Главное правило:

**Каждая основная карточка должна отвечать на три вопроса:**
- Что произошло?
- Почему это требует внимания?
- Что я могу сделать?

Не создавай карточки, которые выглядят полезно, но не имеют понятного действия.

# 05. ВИЗУАЛЬНАЯ СИСТЕМА

## Общий стиль

Apple Minimalism / iOS 26-inspired.

- Чистый белый фон.
- Чёрные акценты.
- Крупная системная типографика.
- Много свободного пространства.
- Минималистичные иконки.
- Нежные серые поверхности.
- Тонкие разделители.
- Округлые карточки.
- Предсказуемая навигация.
- Лёгкие микроанимации.
- Никакой визуальной перегрузки.

SuperApp должен выглядеть как премиальная нативная рабочая система, а не как типовая корпоративная админ-панель.

## Цветовые токены

Background:
#FFFFFF

Primary Text:
#000000

Secondary Text:
#737373

Card Surface:
#F7F7F7

Alternative Surface:
#FAFAFA

Borders:
#E8E8E8

Primary CTA:
#000000

Primary CTA Text:
#FFFFFF

Inactive:
#A3A3A3

Для ошибок, успешных действий и предупреждений допускаются сдержанные семантические цвета, но только по смыслу.

Не использовать разноцветные KPI-карточки и яркие плашки для каждого типа обращения.

Семантика передаётся текстом и иконкой; цвет — лишь дополнительный сигнал.

## Типографика

SF Pro или системный аналог.

Рекомендуемая иерархия:

- Главный заголовок: 30–34 pt, semibold.
- Название главного действия: 17–19 pt, semibold.
- Заголовок секции: 19–22 pt, semibold.
- Текст карточки: 14–16 pt.
- Метаданные: 12–13 pt.
- CTA: 15–17 pt, medium или semibold.
- Крупные числовые показатели: 24–30 pt.

Не использовать слишком мелкие подписи только ради экономии пространства.

## Размеры и отступы

- Горизонтальный padding: 20–24 pt.
- Базовая сетка: 8 pt.
- Радиусы основных карточек: 18–22 pt.
- Расстояния между секциями: 24–32 pt.
- Внутренние отступы карточки: 16–20 pt.
- Минимальная зона касания: 44 × 44 pt.
- Нижняя навигация учитывает Safe Area.

# 07. ОБЛАСТЬ A — HEADER

Верхний левый угол:

**«Доброе утро»**

Ниже крупный заголовок:

**«Сегодня»**

Под ним динамическая дата:

**«Понедельник, 26 октября»**

Дата демонстрационная. В реальном интерфейсе день и число формируются по текущей дате в часовом поясе рабочего пространства.

Для первоначального рынка использовать Asia/Tashkent по умолчанию, если пользователь не указал другой действительный часовой пояс.

Приветствие адаптируется:

- Утром — «Доброе утро».
- Днём — «Добрый день».
- Вечером — «Добрый вечер».

Не изменять содержание задач из-за времени суток.

### Правая часть Header

Компактный аватар пользователя.

Возможные действия:
- Открыть профиль.
- Сменить рабочее пространство при наличии прав.
- Открыть настройки.

Рядом допускается иконка уведомлений, если функция действительно существует.

Если есть непрочитанные системные уведомления — показывать их количество только при наличии достоверных данных.

Не создавать декоративный красный индикатор без события.

### Дополнительная строка контекста

Для самостоятельного риэлтора:

**«Ваше рабочее пространство»**

Для сотрудника:

**«Агентство · Мои задачи»**

Для руководителя:

**«Агентство · Обзор команды»**

Показывать название агентства только если оно действительно известно.

# 08. ОБЛАСТЬ B — СТАТУС ПОДКЛЮЧЕНИЙ

Под Header размести компактную строку состояния источников.

Пример:

**«Рабочие каналы»**

Рядом:
- Телефония.
- Telegram.
- WhatsApp.
- Instagram.

Но не показывать четыре огромные карточки подключения внутри Today.

Использовать один компактный блок или горизонтальный ряд маленьких индикаторов.

Варианты:

### Все подключённые источники работают

Текст:

**«Подключённые каналы работают»**

Дополнительная подпись по нажатию:

«SuperApp получает доступные события из проверенных подключений».

### Один источник отключён

Текст:

**«1 канал требует внимания»**

Кнопка:

**«Проверить»**

### Ни одного подключённого источника

Текст:

**«Подключите рабочие каналы»**

Подпись:

«Звонки и сообщения из подключённых источников смогут появляться здесь».

CTA:

**«Настроить»**

### Синхронизация задерживается

Текст:

**«Обновление Telegram задерживается»**

Подпись:

«Некоторые новые сообщения могут появиться позже».

### Только ручной учёт

Текст:

**«Ручной учёт обращений»**

Подпись:

«Автоматические источники пока не подключены».

Это полноценное допустимое состояние, а не ошибка.

### Критически важное правило

Нельзя показывать фразу «Все обращения получены» при неполном покрытии источников.

Нельзя считать отсутствие новых событий доказательством того, что заявок не было.

Состояние канала определять по серверной проверке интеграции, а не по количеству полученных сообщений.

# 09. ОБЛАСТЬ C — КРАТКАЯ СВОДКА

Под статусом подключения разместить три компактных показателя.

Пример с демонстрационными данными:

**4 — Требуют ответа**

**2 — Пропущенных звонка**

**5 — Задач сегодня**

Использовать горизонтальную сетку 3 × 1.

Каждый показатель должен быть кликабельным.

По нажатию открывается соответствующий отфильтрованный список или состояние текущего экрана.

### Точные подписи

Карточка 1:

**«Без ответа»**

Карточка 2:

**«Пропущенные»**

Карточка 3:

**«Задачи»**

Не писать в подписи «Потерянные клиенты».

### Определение показателей

**Без ответа**

Количество обращений, по которым достаточно данных для определения отсутствия ответа в доступном источнике, либо это состояние явно зафиксировано пользователем.

Если источник не позволяет подтвердить ответ, отображать «Ответ не отмечен» или «Требует проверки».

**Пропущенные**

Подтверждённые события пропущенных рабочих вызовов из доступной телефонии.

Обычные звонки с личной SIM нельзя включать в этот показатель, если приложение реально не имеет законного технического доступа к событиям.

**Задачи**

Открытые задачи с назначенным сроком на сегодня в текущем часовом поясе.

Не смешивать задачи сегодня с уже просроченными без объяснения.

### Если показатель равен нулю

Показывать `0`, когда есть полноценные данные и значение достоверно.

Если источник данных не подключён или данные недоступны, вместо вводящего в заблуждение `0` использовать понятное состояние «Нет данных» или убрать соответствующую карточку.

### Исключение двойного подсчёта

Одно пропущенное обращение может одновременно создать задачу на обратный звонок.

В интерфейсе нужно различать:
- Количество исходных событий.
- Количество обращений, требующих ответа.
- Количество рабочих задач.

Не представлять эти пересекающиеся категории как уникальных потерянных клиентов.

# 10. ОБЛАСТЬ D — ГЛАВНОЕ ДЕЙСТВИЕ ДНЯ

Это **самая важная часть экрана Today**.

Визуально выдели одно действие, которое требует внимания в первую очередь.

Заголовок секции:

**«Начните с этого»**

Ниже — одна крупная карточка.

### Пример карточки

Тип:

**«Просроченный контакт»**

Название:

**«Перезвонить клиенту»**

Контекст:

**«Клиент №128 · Аренда · Чиланзар»**

Пояснение:

**«Контакт был запланирован на вчера, 17:00. Выполнение не отмечено».**

Источник:

**«Задача создана вами»**

Кнопка:

**«Открыть действие»**

Дополнительная иконка:

Меню `…`

### Почему эта карточка важна

Она не должна просто писать «Срочно».

Она обязана объяснить:
- Что известно.
- Когда возникла необходимость.
- На каком основании система считает действие актуальным.
- Что будет следующим шагом.

### Принципы приоритизации

Система ранжирует действия на основании проверяемых правил:

- Явная просрочка назначенного срока.
- Подтверждённый пропущенный рабочий звонок, требующий ответа.
- Новое рабочее обращение без подтверждённой обработки.
- Согласованное действие с близким сроком.
- Время до предстоящего подтверждённого показа.
- Назначенный пользователем приоритет.

Нельзя ранжировать по выдуманной вероятности комиссии.

Не использовать произвольные AI-оценки вроде «98% вероятность потерять клиента».

Если срок ответа или SLA не настроен, не превращать обычное новое сообщение в «критическую просрочку» на основе произвольно выбранного числа минут.

Допускается рекомендация SLA при настройке, но пользователь или организация должны понимать и принять применяемое правило.

### Если приоритет одинаковый

Использовать детерминированный порядок:
- Ближайший или наиболее просроченный срок.
- Более раннее подтверждённое необработанное обращение.
- Стабильный порядок по идентификатору при прочих равных.

### Если система не уверена

Вместо:

«Вы потеряли клиента».

Показывать:

**«Проверьте, нужен ли ответ»**

Пояснение:

«Нет подтверждения выполнения следующего контакта».

# 11. ОБЛАСТЬ E — ТРЕБУЕТ ВНИМАНИЯ

Заголовок:

**«Требует внимания»**

Справа:

**«Смотреть все»**

Показывать первые 3–5 значимых задач.

Не превращать главный экран в бесконечный список 50 обращений.

Если список длинный, открывать отфильтрованный CRM Inbox или полный список действий.

### Категория 1 — Пропущенный звонок

Карточка:

**«Пропущенный звонок»**

Контекст:

«Новый номер · +998 90 ••• •• 42»

Время:

«Сегодня, 10:42»

Источник:

«Рабочая телефония»

Основная кнопка:

**«Перезвонить»**

Вторичное действие:

**«Открыть карточку»**

Важно:

Нажатие «Перезвонить» может открыть системный набор номера или доступную телефонию.

**Открытие набора номера не означает, что вызов состоялся.**

Не помечать звонок как обработанный автоматически.

После возвращения предложить зафиксировать результат.

### Категория 2 — Новое сообщение

Карточка:

**«Новое сообщение»**

Контекст:

«Клиент №84 · Telegram»

Фрагмент:

«Можно сегодня посмотреть квартиру?»

Время:

«Сегодня, 10:15»

Статус:

«Ответ не зафиксирован»

Основная кнопка:

**«Ответить»**

Если разрешена отправка через подключённый Telegram Business:
- Открыть соответствующий доступный диалог или редактор.
- Сохранять подтверждённый результат отправки.

Если отправка из SuperApp недоступна:
- Открыть исходный диалог по поддерживаемому переходу.
- Не считать переход подтверждением ответа.

### Категория 3 — Просроченный контакт

Карточка:

**«Вы обещали связаться»**

Контекст:

«Клиент №32 · Покупка»

Время:

«Вчера, 16:00»

Пояснение:

«Ожидал подборку квартир».

CTA:

**«Подготовить сообщение»**

Дополнительное действие:

«Изменить срок».

### Категория 4 — Запрос требует проверки

Карточка:

**«Проверьте обращение»**

Контекст:

«Instagram · Новый контакт»

Пояснение:

«Сообщение получено, но статус ответа пока неизвестен».

CTA:

**«Открыть обращение»**

Не показывать «Клиент потерян».

### Категория 5 — Заявка без ответственного

Только для соответствующего командного пространства.

Карточка:

**«Новая заявка без ответственного»**

Контекст:

«Рабочий Inbox · Аренда»

CTA:

**«Назначить сотрудника»**

Если пользователь не имеет прав распределять заявки:
- Не показывать активное действие назначения.
- Предусмотреть просмотр своего доступного контекста или информационное состояние.

---

# 12. СТРУКТУРА КАРТОЧЕК

Все рабочие карточки должны использовать единую компонентную систему.

Каждая содержит:

1. Иконку события.
2. Название действия.
3. Клиента или безопасный идентификатор контакта.
4. Канал или источник.
5. Время события либо срок задачи.
6. Короткое объяснение.
7. Основной CTA.
8. Меню дополнительных действий.

### Визуальная логика

Самая важная строка — необходимое действие.

Имя клиента и источник вторичны.

Метаданные не должны конкурировать с CTA.

Используй максимум два-три текстовых уровня внутри карточки.

Не дублируй одну и ту же информацию.

При длинных именах и заголовках допускай перенос текста.

Нельзя обрезать смысл обязательного действия.

---

# 13. БЫСТРЫЕ ДЕЙСТВИЯ

При нажатии на карточку или контекстное меню пользователь должен иметь возможность:

- Открыть связанного клиента.
- Позвонить.
- Подготовить ответ.
- Создать задачу.
- Перенести срок.
- Назначить ответственного при наличии полномочий.
- Отметить действие выполненным.
- Указать результат.
- Отложить.
- Указать «Неактуально».
- Указать «Не мой клиент» при поддерживаемых правилах передачи.
- Посмотреть, почему система предложила действие.

### Главное правило

**Закрытие карточки и выполнение реальной работы — разные вещи.**

Если пользователь нажал «Отметить выполненным», нужно фиксировать именно выполнение задачи или ручное подтверждение результата.

Нельзя превращать ручную отметку пользователя в вымышленный факт успешного телефонного разговора.

---

# 14. ACTION BOTTOM SHEET

Спроектируй универсальный Bottom Sheet для действия на Today.

Пример:

### Заголовок

**«Перезвонить клиенту»**

### Контекст

«Клиент №128»

«Аренда · Чиланзар · До $500»

### Причина появления

**«Почему это здесь?»**

«Вы запланировали контакт на 25 октября, 17:00. Выполнение не отмечено».

### Основные действия

**«Позвонить»**

**«Отметить результат»**

Дополнительные:
- «Перенести».
- «Неактуально».
- «Открыть клиента».

### Если пользователь фиксирует результат

Показать выбор:

**«Чем закончилось?»**

Варианты:
- «Связались».
- «Не ответил».
- «Написал сообщение».
- «Перенесли контакт».
- «Клиент больше не ищет».
- «Другое».

При необходимости — необязательное поле заметки.

Если клиент не ответил, предложить новый контакт.

Если отправлено сообщение вне системы и SuperApp не имеет подтверждения от провайдера, результат должен быть отмечен как введённый пользователем, а не подтверждённый интеграцией.

### После успешного сохранения

Закрыть Bottom Sheet.

Обновить список без полной перезагрузки страницы.

Показать краткое подтверждение:

**«Результат сохранён»**

Если уместно, предложить «Отменить» для обратимого локального изменения, пока оно допустимо.

---

# 15. AI-ПОМОЩНИК В TODAY

AI должен помогать внутри рабочего процесса.

Не создавай отдельного огромного чат-бота посередине Today.

### Как показывать AI

Небольшая поясняющая строка:

**«Подсказка SuperApp»**

Пример:

«Вы обещали отправить подборку вчера. Можно начать с короткого сообщения клиенту».

Кнопка:

**«Подготовить ответ»**

По нажатию:
- Открыть редактируемый черновик.
- Учесть только разрешённую доступную историю.
- Не придумывать актуальные объекты и обещания.
- Не отправлять сообщение автоматически.
- Разрешить редактирование и отмену.

### AI не должен

- Выдумывать потерянные комиссии.
- Называть клиентов потерянными без подтверждения.
- Определять эмоциональное состояние человека без надёжных оснований.
- Подставлять вымышленные данные об объектах.
- Утверждать, что сообщение было прочитано без соответствующего сигнала.
- Автоматически отправлять массовые сообщения.
- Скрывать происхождение значимого вывода.

Если AI временно недоступен, Today продолжает работать с обычными задачами, событиями и детерминированными правилами.

# 16. СЕКЦИЯ «ЗАДАЧИ НА СЕГОДНЯ»

Ниже срочных действий показать:

**«Запланировано сегодня»**

Это отдельная категория от просроченных задач.

Пример:

**11:30 — Отправить подборку**

«Клиент №42 · Двухкомнатная квартира»

**15:00 — Подтвердить показ**

«Юнусабад · Клиент №57»

**17:30 — Связаться с собственником**

«Уточнить актуальность предложения №21»

Каждая строка содержит:
- Время.
- Тип задачи.
- Короткий контекст.
- Состояние.
- Быстрое действие.

Выполненные задачи можно сворачивать в блок:

**«Выполнено сегодня»**

Не нужно создавать сложную полноценную календарную сетку на главном экране.

### Если модуль показов ещё не подключён

Не показывать его как действующий функционал.

Обычные задачи остаются доступны.

### Если задач много

Показывать несколько ближайших и ссылку:

**«Все задачи»**

# 17. НОВЫЕ ВОЗМОЖНОСТИ ОТ МОДУЛЕЙ

Архитектура Today должна быть рассчитана на развитие всего SuperApp.

Но сейчас не нужно отображать все будущие функции.

### Smart Match

Когда модуль реально доступен:

**«Найдено новое совпадение»**

«Запрос №25 · Объект №84»

Подпись:

«Подходят район и бюджет. Актуальность объекта требуется проверить».

CTA:

«Проверить совпадение».

### Property Hub

**«Объект требует обновления»**

«Актуальность не проверялась с указанной даты».

CTA:

«Проверить объект».

### Deals

**«Следующий шаг по сделке»**

«Ожидается подтверждение согласованных условий».

CTA:

«Открыть сделку».

### Commission Tracking

**«Проверьте выплату»**

Показывать только при наличии соответствующего согласованного события.

Не включать потенциальную комиссию в подтверждённый доход.

### Правило модульности

Каждый модуль предоставляет Today структурированные задачи и события.

Отключение модуля не должно уничтожать основную CRM-историю.

Не показывать несуществующие функции как доступные.

---

# 18. РЕЖИМ САМОСТОЯТЕЛЬНОГО РИЭЛТОРА

Для частного риэлтора Today должен быть максимально простым.

Основная последовательность:

1. Новые рабочие обращения.
2. Пропущенные звонки.
3. Обещанные контакты.
4. Текущие задачи.
5. Подходящие объекты — когда модуль активен.

Не показывай:
- KPI чужих сотрудников.
- Управление отделами.
- Сложную воронку агентства.
- Корпоративные роли.
- Настройки комиссии всей команды.

Пользователь должен чувствовать, что SuperApp — **его личный рабочий помощник**.

---

# 19. РЕЖИМ РИЭЛТОРА АГЕНТСТВА

Для сотрудника агентства основной Today выглядит так же, но учитывает права доступа.

Показывать:
- Назначенные ему обращения.
- Его задачи.
- Его клиентов.
- Доступные ему рабочие события.
- Командные задачи, если они назначены пользователю.

Не показывать личные переписки других сотрудников или конфиденциальные записи, на которые нет разрешений.

Если руководитель переназначил заявку:
- Обновить ответственного.
- Предусмотреть информацию об изменении.
- Не оставлять старому сотруднику доступ без основания.

Если подключён общий корпоративный источник, он должен соответствовать настройкам агентства.

---

# 20. РЕЖИМ РУКОВОДИТЕЛЯ АГЕНТСТВА

Руководителю необходима дополнительная возможность переключения:

**«Мои» / «Команда»**

Используй компактный segmented control под Header либо в предусмотренной области контекста.

### Мои

Обычный личный Today:
- Мои клиенты.
- Мои задачи.
- Мои контакты.

### Команда

Показывать:
- Необработанные командные обращения.
- Заявки без ответственного.
- Просроченные рабочие задачи команды.
- Обращения, требующие переназначения.
- Действия, по которым нужен контроль.

Пример заголовка:

**«Требует внимания команды»**

Пример карточки:

**«2 заявки без ответственного»**

Подпись:

«Обращения ожидают назначения».

CTA:

**«Распределить»**

Не превращать режим руководителя в инструмент слежки за личной жизнью сотрудников.

Не показывать активность из личных каналов, не подключённых к агентству на надлежащих основаниях.

Не создавать KPI «Кто хуже всех работает» без контекста.

Главная цель режима:

**Помочь распределить работу и не оставить заявки без ответа.**

# 21. NAVIGATION — НИЖНЯЯ ПАНЕЛЬ

Today — корневой экран приложения.

Для полной версии SuperApp использовать пять основных разделов:

**Сегодня | Входящие | Клиенты | Объекты | Сделки**

Иконки:
- Сегодня — дом или рабочая панель.
- Входящие — Inbox.
- Клиенты — группа людей.
- Объекты — здание.
- Сделки — рукопожатие или документ.

Активная вкладка Today — выразительная чёрная иконка и подпись.

Неактивные — нейтрально-серые.

### Для раннего MVP

Если Property Hub и Deals ещё не реализованы, не показывай фиктивные полноценные разделы.

Используй упрощённую навигацию:

**Сегодня | Входящие | Клиенты | Ещё**

Сохраняй последовательность основных разделов и не меняй навигацию без явного продуктового обновления.

Будущие модули могут находиться в «Ещё» и подключаться позже.

### Быстрое добавление

Предусмотри доступную кнопку `+`, встроенную в подходящую область интерфейса.

При нажатии открывается Quick Action Bottom Sheet:

**«Что добавить?»**

Варианты:
- «Нового клиента».
- «Рабочее обращение».
- «Задачу».
- «Объект» — если доступен соответствующий модуль.
- «Показ» — если доступен соответствующий модуль.

Не создавать одновременную конкуренцию между плавающей кнопкой и несколькими большими CTA.

# 22. EMPTY STATES

Спроектируй разные состояния отсутствия данных.

## A — Новый пользователь

Ничего не подключено, клиентов и задач ещё нет.

Заголовок:

**«Ваш рабочий день начинается здесь»**

Описание:

«Добавьте первого клиента или подключите рабочий канал, чтобы управлять обращениями и следующими действиями».

CTA:

**«Добавить клиента»**

Вторичная кнопка:

**«Подключить канал»**

Не показывать вымышленные звонки и сообщения.

## B — Каналы подключены, обращений ещё нет

Заголовок:

**«Новых обращений пока нет»**

Описание:

«Когда поддерживаемый подключённый канал передаст новое событие, оно появится здесь».

Действие:

«Открыть подключения».

Не утверждать, что никаких звонков вообще не поступало.

## C — Всё обработано

Если данные достоверны:

**«На сегодня всё обработано»**

Подпись:

«Нет открытых действий, требующих внимания, по доступным данным».

Дополнительное действие:

«Посмотреть выполненное».

Не показывать ложный успех, если источники временно недоступны.

## D — Только ручная CRM

**«Добавьте первую задачу»**

Описание:

«SuperApp поможет помнить о клиентах и следующих контактах даже без подключённых каналов».

CTA:

«Создать задачу».

## E — Нет задач сегодня, но есть будущие

**«На сегодня задач нет»**

Подпись:

«Следующие запланированные контакты находятся в вашем списке задач».

Действие:

«Посмотреть задачи».

## F — Частичная синхронизация

**«Данные могут быть неполными»**

«Один из рабочих каналов временно не обновляется».

CTA:

«Проверить подключение».

Это не обычный Empty State, а предупреждение о неполном покрытии.

# 23. LOADING И SKELETON STATES

При загрузке Today:
- Отобразить Header.
- Скелетон основных показателей.
- Скелетон приоритетной карточки.
- Скелетон нескольких строк задач.

Не показывать выдуманные числовые значения во время загрузки.

Не использовать агрессивную бесконечную анимацию.

### Обновление данных

Предусмотри pull-to-refresh там, где он соответствует платформе.

Обновление не должно очищать весь экран до белого состояния.

Если доступен ранее подтверждённый кэш:
- Сохранить видимые данные.
- Показать, что они обновляются.
- Отметить устаревший статус при необходимости.

---

# 24. OFFLINE MODE

Если интернет пропал:

Показывать компактный статус:

**«Нет соединения»**

Описание:

«Показаны последние сохранённые данные. Новые обращения могут быть недоступны».

Дата последнего успешного обновления:

**«Обновлено в 10:42»**

Время показывается только если действительно известно.

### Доступные действия

- Просмотр локально сохранённых данных с учётом безопасности.
- Подготовка заметки, если реализован безопасный offline draft.
- Создание локальной задачи, если поддерживается очередь синхронизации.

### Недоступные действия

- Получение актуальных внешних событий.
- Подтверждённая отправка через интернет-сервисы.
- Актуализация статуса сообщения.
- Любые действия, которым требуется сервер и которые не поддерживают offline queue.

Если действие сохранено только локально:

**«Ожидает синхронизации»**

Не показывать «Сохранено в CRM» до подтверждения сервера.

При восстановлении связи:
- Обработать очередь с защитой от дублей.
- Показать состояние синхронизации.
- Не терять подтверждённые результаты.

# 25. ERROR STATES

### Не загрузился Today

Подпись:

CTA:

**«Повторить»**

### Ошибка одного блока

Пример:

CTA:

«Повторить».

**«Результат не сохранён»**

Подпись:

«Попробуйте ещё раз. Ваши изменения пока не подтверждены».

CTA:

«Повторить».

### Недостаточно прав

**«Нет доступа к этому действию»**

Описание:

«Обратитесь к администратору рабочего пространства, если доступ необходим».

Не показывать конфиденциальные данные в ошибке.

### Истёк срок авторизации источника

**«WhatsApp требует переподключения»**

CTA:

«Восстановить доступ».

# 26. ДАННЫЕ И ПРАВИЛА ДОСТОВЕРНОСТИ

Это фундамент доверия к Today.

Система должна отличать:

### 1. Подтверждённое событие

Например:

«Пропущенный звонок поступил в подключённую АТС».

### 2. Зафиксированную задачу

Например:

«Перезвонить сегодня в 15:00».

### 3. Подтверждённое выполнение

Например:

«Пользователь сохранил результат обратного звонка».

### 4. Предположение AI

Например:

«Вероятно, требуется уточнить интерес клиента».

### 5. Отсутствие данных

Например:

«Состояние ответа неизвестно».

Различай эти случаи визуально и текстово.

### Запрещено

- Показывать гипотезу как доказанный факт.
- Называть клиента потерянным из-за просрочки.
- Утверждать, что звонок завершён, если открылся только системный набор номера.
- Утверждать, что сообщение отправлено, если пользователь его только скопировал.
- Объединять разные контакты по одному предположению AI без достаточных оснований.
- Показывать доход или упущенную комиссию на основании неподтверждённой сделки.
- Скрывать проблемный статус подключения.

### Отложенные события

Если событие поступило с задержкой, сохранять исходное время события и отдельно учитывать время его поступления в CRM.

Не создавать новую «срочную» задачу задним числом без объяснения.

### Дубликаты

Один и тот же звонок или webhook не должен создавать несколько одинаковых карточек.

Если несколько каналов относятся к одному клиенту, объединение допустимо только при подтверждённых идентификаторах или согласованном действии пользователя.

# 27. ПРИОРИТЕТЫ И СОРТИРОВКА

Создай понятную систему сортировки Today.

### Группы

**Срочно**

Подтверждённые просрочки и действительно требующие оперативного внимания рабочие события.

**Сегодня**

Задачи с назначенным сроком на текущий день.

**Проверить**

Случаи с недостаточными данными.

### Сортировка

Внутри групп:
- Сначала явные пользовательские и командные приоритеты по утверждённым правилам.
- Затем реальные сроки.
- Затем время события.
- Затем стабильный порядок остальных записей.

Не использовать AI как непрозрачный механизм, который произвольно меняет карточки местами.

### Контроль пользователя

Допускается компактное действие:

**«Настроить приоритеты»**

Но не добавляй на главный экран сложный конструктор правил.

Настройки можно открыть через локальный Bottom Sheet или предусмотренный раздел приложения.

# 30. MICROINTERACTIONS И MOTION

### Первое появление Today

Плавное проявление содержимого.

Не показывай длинную приветственную анимацию.

### Новое рабочее обращение

Если приложение открыто, новая карточка появляется с мягким переходом.

Не перемещай резко весь список, когда пользователь читает другую карточку.

Допускается компактное уведомление:

**«Есть новые обращения»**

По нажатию пользователь решает обновить позицию списка.

### Выполнение задачи

- Карточка меняет состояние.
- Показывается короткое подтверждение.
- Список плавно обновляется.
- При необходимости доступна отмена обратимого действия.

### Открытие Bottom Sheet

Системная плавная анимация.

Скорость ориентировочно 180–260 мс.

### Переключение «Мои / Команда»

Сохранять Header и навигацию.

Обновлять только содержимое рабочей области.

### Reduce Motion

Все декоративные перемещения должны быть отключаемыми.

Реакция интерфейса остаётся понятной через текст и состояние.

Не применять:
- Постоянно пульсирующие красные индикаторы.
- Тряску карточек.
- Агрессивные конфетти-анимации.
- Навязчивые звуковые сигналы.
- Автоматическую прокрутку списка.

# 32. ПРИВАТНОСТЬ И БЕЗОПАСНОСТЬ

SuperApp работает с чувствительными рабочими данными: телефонами, сообщениями, запросами клиентов и сделками.

### Принципы

- Минимально необходимый доступ.
- Разделение личных и агентских данных.
- Проверка прав на сервере.
- Маскирование контактных данных там, где полный номер не нужен.
- Отсутствие текста переписок в уведомлениях на заблокированном устройстве без выбранных пользователем настроек.
- Безопасное хранение разрешённых событий.
- Прозрачность источников.
- Возможность отключения интеграций.
- Защита от утечки через аналитику и журналы ошибок.

### Важные ограничения интеграций

**Telegram Business**

Только разрешённые чаты и операции подключённого бизнес-бота.

**WhatsApp Business**

Только доступные официальные бизнес-интеграции, с учётом прав и ограничений платформы.

**Instagram**

Поддерживаемые сообщения профессиональных аккаунтов и предоставленные разрешения.

**Телефония**

События подключённой АТС или технически допустимых нативных механизмов.

Не обещать доступ ко всей истории личной SIM.

### Веб-версия

Next.js и Tailwind CSS не предоставляют прямой доступ к системному журналу звонков смартфона.

Не изображать Today так, будто браузер самостоятельно перехватывает все обычные вызовы.

# 34. EDGE CASES

Предусмотри и опиши поведение для следующих ситуаций.

1. После регистрации ещё нет ни одного клиента.
2. Пользователь пропустил подключение каналов.
3. Телефония подключена, Telegram нет.
4. WhatsApp подключён, но разрешение на сообщения отсутствует.
5. Истёк токен Instagram.
6. Сервис Telegram временно недоступен.
7. Вызов был пропущен, но номер скрыт.
8. Один номер встречается у нескольких клиентов.
9. Один человек пишет из двух разных аккаунтов.
10. Система не может подтвердить, что клиенту ответили.
11. Пользователь позвонил, но клиент не ответил.
12. Пользователь скопировал сообщение, но не отправил его.
13. Пользователь отметил задачу выполненной вручную.
14. Два сотрудника одновременно открыли одну заявку.
15. Руководитель переназначил клиента во время работы агента.
16. Пропущенный звонок поступил с задержкой.
17. Одно событие пришло через webhook дважды.
18. Сегодня нет задач, но есть просроченные.
19. Сегодня выходной, но рабочие обращения продолжают поступать.
20. Изменился часовой пояс пользователя.
21. Пользователь вернулся после семи дней отсутствия.
22. За время отсутствия накопилось 100 обращений.
23. Интернет отключился во время сохранения.
24. Пользователь создал задачу офлайн.
25. Пользователь удалил или архивировал клиента.
26. Пользователь не имеет права видеть конкретный рабочий источник.
27. Сотрудник покинул агентство.
28. Доступен только один модуль SuperApp.
29. AI временно отключён.
30. Нет достоверных данных для вычисления показателя.
31. Данные одного источника обновлены, другого — нет.
32. Пользователь включил крупный шрифт.
33. Одна задача связана с несколькими событиями.
34. Одно обращение одновременно является пропущенным звонком и имеет задачу обратного контакта.
35. Действие уже выполнено с другого устройства.
36. В CRM поступило новое сообщение после ручной отметки задачи завершённой.

В каждом случае:
- Не терять данные.
- Не создавать ложные статусы.
- Не дублировать работу.
- Показывать понятное следующее действие.
- Соблюдать права доступа.
- Не делать необратимых действий молча.

# 40. ФИНАЛЬНАЯ UX-ЦЕЛЬ

Создай премиальный, минималистичный и интеллектуальный **главный экран Today для SuperApp**, который становится ежедневной отправной точкой работы риэлтора.

Пользователь не должен чувствовать, что ему предстоит вести сложную CRM.

Он должен чувствовать, что **SuperApp уже организовал доступную рабочую информацию и помогает определить следующие действия**.

Главный экран должен отвечать:

**Кто обратился?**

**Кому нужно ответить?**

**Кому я обещал перезвонить?**

**Что требует внимания сегодня?**

**Какое действие я могу выполнить прямо сейчас?**

Today — не Dashboard.
