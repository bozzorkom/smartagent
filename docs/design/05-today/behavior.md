# Today №05 — правила рабочего дня и достоверности

Дата: 27 октября 2026. Шаг 2 [плана](../../superpowers/plans/2026-10-27-today-full-spec-plan.md).

Статус: проектное решение для следующих шагов, не реализованное поведение приложения. Основания: [задание](../../prompt/5.md), §09–10, 26–27; [матрица](coverage.md), G01–G03, G11. Ни реальные подключения, ни серверное хранение не добавляются. Все примеры — демо. Детальная матрица ролей относится к шагу 4.

## 1. Минимальный контракт сущностей

| Сущность | Необходимые сведения |
|---|---|
| Событие | Внутренний ID; пространство; источник и аккаунт; ID события провайдера, если существует; тип; время возникновения `occurredAt` и получения `receivedAt` отдельно; версия; основание достоверности; доступность; идентификатор контакта в источнике; связь с обращением. Неизвестное время не заменяется временем получения. |
| Обращение | ID; пространство; ссылки на события; источник; состояние ответа: подтверждённо отсутствует / отмечено пользователем / неизвестно / обработано; ответственный; допустимые действия; связанный клиент, если связь подтверждена; статус открыто / обработано / неактуально; версия. |
| Задача | ID; автор; ответственный; пространство; название; состояние; срок одного из видов: точное время, календарная дата, без срока; пояс срока; связи с обращением/клиентом; явный приоритет и его автор; даты создания, изменения и выполнения. |
| Клиент | ID; пространство; имя или безопасное обозначение; подтверждённые связи с идентификаторами источников; активен / архивирован / удалён; доступность. Номер телефона не является уникальным ID клиента. |
| Результат | ID действия; автор; время; исход; заметка; ссылки на исходные обращение, задачу, события и клиента; основание: ручная отметка или подтверждение источника; состояние сохранения: черновик / сохраняется / сохранено локально в демо / подтверждено сервером / ошибка / результат неизвестен. Последние серверные состояния здесь только проектируются. |
| Источник / модуль | ID; пространство; состояние подключения; отдельные возможности чтения/отправки/назначения; последнее успешное обновление; полнота данных; ошибка; доступ пользователя. «Подключён» не означает наличие всех разрешений. |

Журнал сохраняет исходные связи и авторство. После создания клиента из обращения его история включает записи по `clientId` и по связанному `itemId`, без дублирования по ID записи журнала. Нельзя задним числом приписывать клиенту неподтверждённо связанные события.

## 2. Пять оснований достоверности

| Основание | Подпись / допустимый вывод | Чего не утверждаем |
|---|---|---|
| Подтверждённое событие | «Пропущенный вызов · АТС · 10:15»; в прототипе дополнительно «Демо» | Что клиент потерян или повторного контакта не было в другом канале |
| Запланированная задача | «Создано вами · срок сегодня, 15:00» | Что контакт состоялся |
| Результат пользователя | «Разговор отмечен вами · 15:10» | Что провайдер подтвердил разговор |
| Предположение AI | «Предложение AI · требует проверки», с доступным основанием | Факт ответа, идентичность клиента, срок или автоматическое закрытие |
| Нет данных | «Ответ не подтверждён» / «Нет данных» и причина | Ноль событий, отсутствие ответа или успешную синхронизацию |

Это независимые основания, не шкала уверенности. Копирование текста и открытие набора номера — намерения, а не результаты контакта. Свежесть показывается отдельно: установленный факт события не исчезает при сбое источника, но текущее состояние ответа может быть неизвестно.

## 3. Сроки и смена дня

- Базовый пояс отображения — Asia/Tashkent; допускается другой валидный IANA-пояс. Все примеры ниже используют 27.10.2026, 12:00 Asia/Tashkent.
- Точный срок хранит абсолютный момент и пояс ввода. Просрочено, если срок строго раньше текущего момента и задача открыта. Ровно в срок: «Срок сейчас», ещё не просрочено.
- Задача с сегодняшним сроком 11:00 в 12:00 уже просрочена, хотя календарная дата сегодняшняя.
- Срок только с датой не получает выдуманное время 00:00. Он истекает при наступлении следующего дня в сохранённом поясе задачи. Подпись: «До конца дня». При отличии от текущего пояса показывать пояс срока.
- Задача без срока не является просроченной и не входит в «Задачи сегодня»; отдельный список «Без срока».
- Смена пояса не меняет абсолютные сроки и исходные календарные даты. Перегруппировка точных сроков выполняется в новом поясе; календарные сроки сохраняют свой пояс и получают явную подпись. Просрочка календарного срока проверяется в его собственном поясе.
- В полночь и при возвращении на экран обновляются дата, классификация и счётчики. Открытая форма не закрывается; ввод не теряется. Нет автоматического переноса вчерашних задач на сегодня.
- Перенос изменяет срок той же задачи, не создаёт копию. Журнал хранит старый и новый срок. Отмена восстанавливает их, если запись не изменилась после действия; иначе требуется разбор конфликта.
- Выходной не скрывает события и задачи. SLA по рабочим часам применяется только при наличии заданного календаря и правила; таких правил по умолчанию нет.

## 4. Сводка и единый набор данных

Все показатели, hero и списки используют один снимок данных, один момент времени, пространство, роль и область «Мои / Команда». Показатели считаются до ограничения количества карточек на главной. Нажатие каждого показателя открывает именно его набор; число равно количеству уникальных записей полного списка, а не видимых первых карточек.

| Показатель | Единица и включение | Исключения |
|---|---|---|
| Без ответа | Уникальные открытые обращения: отсутствие ответа подтверждено доступным источником либо явно отмечено пользователем; основания различаются в списке | Неизвестное состояние, закрытые, неактуальные, недоступные обращения. Сам факт пропущенного звонка не доказывает текущее отсутствие ответа |
| Пропущенные | Уникальные подтверждённые события рабочих пропущенных вызовов, по которым ещё требуется действие | Дубли событий, обработанные события, личная SIM без доступа. Подпись уточняет «Требуют обработки», это не суточная статистика всех звонков |
| Задачи | Открытые задачи со сроком на сегодня. Уже прошедшее время сегодняшней задачи остаётся в этом числе, но отмечается просроченным | Выполненные, отменённые, будущие и без срока. Просроченные прежних дней показываются отдельно |

Под «Задачи» при наличии просрочек: «Из них N просрочены сегодня; ещё M — за прошлые дни». Общий список «Просроченные» включает N и M без дублей; он также кликабелен. Для календарных сроков другого пояса отдельная явно подписанная группа исключает неоднозначное слово «сегодня»; они не смешиваются с числом сегодняшних задач текущего пояса.

Категории пересекаются и не складываются в число клиентов. Не показывать общий итог суммой трёх метрик. Если нужен размер объединённой очереди, считать уникальные рабочие действия, а не клиентов.

### Нет данных, ноль и неполнота

- `0` допустим только при успешно полученном полном пустом наборе для доступной области; в демо — при явно заданном полном сценарии.
- Нет источника/разрешения/первой загрузки: «Нет данных», не `0`; loading показывает skeleton.
- Частичные сведения: «Известно N · данные неполные», раскрытие источников и времени обновления. Список содержит ровно эти N известных записей.
- Сбой источника не удаляет ранее доступные записи: они остаются с отметкой устаревания, если права сохраняются. Недоступные сейчас внешние действия блокируются.
- Отзыв прав отличается от сбоя: содержимое скрывается, записи исключаются из разрешённого набора без раскрытия количества чужих записей.
- «Всё обработано» разрешено только при полном актуальном доступном наборе без открытых действий. Иначе: «В известных данных нет открытых действий» плюс причина неполноты.

## 5. Единый приоритет

Кандидаты включают реальные задачи и действия по обращениям, не только карточки событий. Выполненные/неактуальные, недоступные и будущие задачи исключены из hero. Карточка, представленная в hero, не дублируется в очереди, но остаётся в соответствующих счётчиках и полном списке.

1. **Срочно:** открытые задачи с истёкшим сроком, подтверждённое нарушение явно заданного SLA, событие с действующим утверждённым правилом оперативного приоритета. Сам возраст сообщения или пропущенного звонка не создаёт SLA.
2. **Сегодня:** непросроченные задачи текущего дня и подтверждённые открытые действия без срока; последние подписываются «Без срока · в работе», а не получают выдуманный срок сегодня.
3. **Проверить:** неизвестный результат контакта, неоднозначная идентичность или актуальность. Первое действие — уточнить, не отправить сообщение и не объединить клиента.

Внутри группы: явный разрешённый приоритет (высокий, обычный, низкий), затем ближайший реальный срок, затем наиболее раннее время события/создания задачи, затем стабильный ID по возрастанию. Отсутствующий срок или время идут после известных; время получения не выдаётся за время события. Ручной приоритет не превращает неизвестность в подтверждённую срочность. AI не меняет ранжирование.

Hero — первый допустимый кандидат. Если есть только проверки, hero объясняет необходимость проверки. Если кандидатов нет, показывается соответствующая пустота и создание задачи, не искусственный приоритет. Фильтр списка не меняет глобальный hero; его область явно остаётся «Мои» или «Команда».

Для каждого приоритета доступно объяснение: основание, срок с поясом, источник, следующий шаг. Новые события помещаются в буфер «Есть новые события»; применение обновления пересчитывает порядок без потери открытого действия и позиции чтения. Дедлайн меняет статус и счётчики, но не заменяет карточку под рукой во время взаимодействия.

## 6. Идентичность, закрытие и новые события

- Дедупликация подтверждённых событий: пространство + источник + аккаунт + provider event ID. Повтор с той же версией не добавляет карточку, счётчик или журнал; новая версия обновляет факт с сохранением истории.
- При отсутствии надёжного ID совпадение времени/номера — только возможный дубль. Автоматически не объединять; показать проверку. Разные источники не дедуплицируются по одному телефону.
- Несколько событий могут относиться к одному обращению; связи должны быть подтверждены. Два аккаунта одного клиента не означают одно событие.
- Закрытие панели ничего не закрывает в модели. Результат или «Неактуально» изменяет только явно перечисленные записи после подтверждения.
- «Не ответил» фиксирует попытку, но не доказывает достижение клиента. Обработанное событие вызова может уйти из «Пропущенных», а открытое обращение остаться; follow-up становится отдельной задачей.
- Новое входящее событие после выполнения не отменяет старый результат. Создаётся новое открытое действие в связанном обращении либо новое обращение по установленной связи. Поздно поступившее старое событие сначала сопоставляется с результатом: автоматического повторного открытия нет, при неопределённости — «Проверить».
- Неизвестный результат сохранения не показывается как успех или гарантированная ошибка. Повтор должен использовать тот же ID действия; в текущем прототипе нет серверной гарантии или долговечной offline-очереди.

## 7. Ручной разбор контрольных примеров

| Пример | Отображение и счётчики | Действие / объяснение |
|---|---|---|
| Задача вчера 17:00, других событий нет | Hero «Просроченный контакт»; задачи сегодня 0; просрочки прошлых дней 1 при полном наборе | Открыть задачу; она кандидат общего приоритета, несмотря на пустые обращения |
| Задача сегодня 11:00, сейчас 12:00 | Hero «Срок прошёл в 11:00»; задачи 1, из них просрочена сегодня 1 | Не ждать следующего календарного дня |
| Подтверждённый вызов со скрытым номером | Пропущенные 1; без ответа не увеличивается без отдельного основания; «Номер скрыт» | Открыть детали / отметить исход; перезвонить и привязать по номеру нельзя |
| Один человек пишет из двух аккаунтов | Два обращения без ответа дают 2; при подтверждённой связи клиент один | Не складывать категории в число клиентов, не объединять по догадке AI |
| Вызов 09:00 получен в 11:50 | «Вызов 09:00 · получено 11:50»; пропущенные 1, если ещё требует обработки | Возраст не создаёт срочность. При позднем событии после исхода в 10:00 — проверить связь, не создавать просроченную задачу задним числом |
| Вызов + задача на сегодня 15:00, ответа ещё нет и это подтверждено | До обработки: без ответа 1, пропущенные 1, задачи 1; это не три клиента | После отметки попытки без ответа: пропущенные 0, без ответа 1, задачи 1; задача не дублируется. После подтверждённого успешного исхода обращение закрывается, задачу выполняют явно |
| Двойная доставка одного provider event ID | Те же карточки и числа, что после первой доставки | Без нового hero и повторного журнала |
| Сбой Telegram после успешного чтения двух обращений | «Известно 2 · данные устарели», те же две доступные записи | Не ноль и не «Всё обработано»; повторить обновление |
| Новое сообщение после закрытия | Новый открытый рабочий шаг; прежний исход сохранён | В буфер новых событий, без перезаписи истории |

Разбор — проверка непротиворечивости спецификации, не выполненные автоматические или браузерные тесты.

## 8. Передача следующим шагам

G01–G03 и G11 получили проектные правила, но не исправлены в приложении. Шаг 3 использует единый hero, ограниченную очередь и отдельные полные списки; шаг 4 уточняет права; шаги 5–6 описывают переходы, конфликты и восстановление. Эти правила не дают основания повысить статусы реализации в coverage.md. Сроки, сортировка, счётчики и дедупликация потребуют отдельных тестов при последующей реализации.
