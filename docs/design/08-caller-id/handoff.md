# №08 — Caller ID: передача UX и реализации

27 октября 2026. Пользователь подтвердил веб-прототип вместо Figma. Это исполняемое локальное демо и спецификация; нативная телефония, сервер и публикация не входят в результат этого этапа.

## Как открыть

`http://localhost:3000/` → Today → **Ещё → Звонки и Caller ID**. В «Примеры и состояния» доступны 22 вымышленных примера, обновления события, ошибки, блокировка и выбор звонков сеанса. События появляются также в Today/Inbox и связанных карточках клиентов. Данные очищаются при перезагрузке.

Основной путь: известный вызов → результат → необязательная заметка/будущий срок → сохранить → общая история/задача. Пропущенный: намерение обратного набора либо напоминание; закрытие только после явного результата. Неизвестный: создать контакт или подтвердить связь. Ни одного реального звонка или сообщения эти действия не выполняют.

## Артефакты и модель

- `design.md` — композиция, токены, варианты и первичные платформенные источники.
- `../../../components/caller-workspace.tsx` и `.css` — тексты интерфейса, формы, контекст и состояния.
- `../../../components/caller-platforms.tsx` — независимые системные иллюстрации.
- `../../../components/caller-data.ts` — типы и примеры; `today-state.ts` — общая модель и операции.
- `../../../tests/caller-state.test.mjs` — 26 регрессий звонков. Ещё 18 тестов проверяют общие сценарии CRM.
- [Браузерная QA](../../qa/2026-10-27-caller-id-check.md).

Один callId = provider + externalId. `sequence` сортирует события источника; `businessVersion` защищает ручной результат. `startedAt`, `receivedAt`, `endedAt`, `savedAt` не заменяют друг друга. Телефон нормализуется; скрытое/невалидное значение не даёт обратного набора. Результат хранит operationId и источник user; задача имеет отдельный ID/callId/clientId/scope/dueAt.

Техническое обновление не стирает результат и черновик. Номер, исправленный после привязки, снимает прежнюю идентичность и требует подтверждения; старые задачи не переносятся автоматически. Событие и ручной итог проецируются в один элемент Inbox/Today. Для API нужны канонический ID разговора, порядок событий, транзакция результата+задачи, серверная идемпотентность, tenant/ACL и механизм восстановления после сетевого сбоя. Локальная функция reducer этих серверных гарантий не предоставляет.

## Матрица статусов и действий

| Техническое состояние | Действия в прототипе | Что не подтверждено |
|---|---|---|
| incoming / connecting / active | Контекст CRM; только demo-VoIP имеет answer/decline/end | Бизнес-результат нельзя сохранить до завершения |
| ended | Ручной исход, заметка, будущая задача | Наличие и содержание разговора не выводятся из длительности |
| missed | Намерение набора, напоминание, причина отсутствия callback | Набор не равен ответу; «Связались» — отдельная ручная отметка обратного контакта |
| answeredElsewhere | Сведения о разрешённом командном событии, Inbox | Не личный missed, клиент не переназначается |
| declined / canceled / failed | Свой технический статус + ручной результат | Не считать их одинаковыми или состоявшимся разговором |
| unknown | Уточнение результата вручную | Причина/длительность/ответ могут быть неизвестны |

Ручные исходы: **Связались / Не ответил / Перезвонить позже / Не требует ответа / Не относится к работе / Другое**. Для «Перезвонить позже» обязателен будущий срок; для «Не требует ответа» — причина. Только заметка сохраняется без закрытия обращения. При конфликте чужой результат остаётся, свой текст можно добавить отдельной заметкой. Реального автоматического merge нет.

## Платформы, разрешения и приватность

| Поверхность | Представление | Необходимая реальная зависимость |
|---|---|---|
| iOS Call Directory | Минимальная системная подпись, off/outdated | Нативное расширение, справочник и включение пользователем |
| iOS Live Caller ID Lookup | Отдельное пояснение инфраструктуры | Нативное расширение, сервер и процедуры Apple |
| iOS CallKit | Управляемый VoIP, отличный от определения номера | Собственный VoIP-сервис и интеграция с системным интерфейсом |
| Android | Минимальная системная иллюстрация, недоступная роль | Поддерживаемый call-screening, версия/OEM, пользовательский выбор и политика магазина |
| АТС events | Контекст и post-call, без answer/decline | Подтверждённое API событий провайдера |
| VoIP | Явно обозначенное переключение примера | В продукте — реальное право и API управления; здесь только симуляция |
| Обычная SIM в вебе | Ручная CRM/подключение каналов | Автоматические события не предполагаются |

[Apple CallKit](https://developer.apple.com/documentation/callkit) предоставляет системный интерфейс VoIP, а коммуникации реализует сервис приложения. Это отдельный механизм от расширений определения номера. [Google Play](https://support.google.com/googleplay/android-developer/answer/10208820?hl=en-GB) ограничивает доступ к SMS/Call Log: роль call-screening не означает автоматическое разрешение на весь журнал; обоснование доступа и применимость исключений проверяются перед нативным релизом. Дополнительные первичные ссылки — в `design.md`.

Приватные CRM-поля не выводятся в системной иллюстрации. Для рабочего blocked/restricted состояния скрыты имя, номер, запрос и заметки. Реальный сервер должен фильтровать данные до передачи клиенту, а не полагаться на CSS. Номер не подтверждает личность и не даёт согласие на маркетинг. Нет микрофона, записи, автоперезвона, отправки, разрешений ОС или телеметрии с персональными данными.

## Адаптивность и доступность

Проверены ширины 320/393/430/1024, малая высота 568 и поворот 852×393. Для крупного текста — 18 px в основных строках и полях, 16 px в метаданных, один столбец исходов. Зоны кнопок от 44×44 CSS px. Общий native `<dialog>` изолирует модальный контекст; подписи полей, radio/fieldset, статусы и ошибки доступны семантически. После сохранения фокус переходит на результат; при закрытии с черновиком — на предупреждение. Reduce Motion отключает необязательные эффекты. Это браузерная проверка: нативные Dynamic Type, VoiceOver, TalkBack и экранная клавиатура телефона ещё требуют устройств.

## Все 60 edge cases

Общее правило таблицы: сохраняются только полученное событие и явно подтверждённый ввод. Неизвестные данные не дополняются. «Демо» обозначает локальное поведение; «Концепт/контракт/граница» — спецификацию или зависимость, а не реализованную production-возможность.

| № | Случай брифа | Покрытие | Что видно, что известно/неизвестно, действия и сохранение |
|---|---|---|---|
| 1 | Известный клиент звонит с основного номера. | Демо | Имя и разрешённый запрос из единственного совпадения; личность не подтверждена. Открыть CRM, сохранить ручной результат/задачу. |
| 2 | Известный клиент звонит с дополнительного номера. | Граница модели | Поле основного телефона поддержано; отдельного реестра дополнительных номеров нет. Нераспознанный номер остаётся неизвестным до явной связи; alias-реестр нужен на сервере. |
| 3 | Номер отсутствует в CRM. | Демо | Нейтральный номер без выдуманного запроса. Создание или связь только по подтверждению; сохраняются номер, введённые поля и источник. |
| 4 | В CRM несколько контактов с одним номером. | Демо | Контексты скрыты до выбора доступной карточки; автоматического выбора первого совпадения нет. Сохраняется явная связь. |
| 5 | Один клиент имеет несколько активных запросов. | Демо-концепт | Вариант «Несколько запросов»: два раздельных демо-запроса, подробности раскрываются. Полноценный реестр запросов и выбор активного запроса — зависимость CRM. |
| 6 | Звонит собственник. | Демо-концепт | Отдельный пример собственника и объекта №248. Это подписанный контекст; модуль объекта и его переход пока не реализованы. |
| 7 | Звонит покупатель. | Дизайн-контракт | Показывать подтверждённый запрос покупки из CRM. Данные роли не угадывать; можно изменить запрос в Client 360°. Отдельного seed-примера покупателя нет. |
| 8 | Звонит арендатор. | Демо | Основной пример аренды: район, комнаты, бюджет с единицей /мес. Остальные параметры неизвестны; сохраняется только пользовательский ввод. |
| 9 | Звонит партнёр. | Дизайн-контракт | Нейтральный контакт и подтверждённая роль партнёра, без запроса покупателя по умолчанию. Отдельная модель партнёра отсутствует. |
| 10 | Номер скрыт. | Демо | «Номер не определён»; обратный набор отключён. Можно оставить заметку/ручной результат и явно создать контакт без номера. |
| 11 | Номер отображается некорректно. | Модель | Невалидный номер нормализуется в undefined; совпадения и набор недоступны. Исходный невалидный идентификатор не используется как телефон. |
| 12 | Номер потенциально подменён. | Демо + граница | Номер не удостоверяет личность; это объяснено в источнике. Уточнение номера скрывает прежнюю связь и требует нового выбора. Антиспуфинг не реализован. |
| 13 | Контакт находится в архиве. | Демо | Нейтральный архивный контакт без приватного запроса. Нет автоматического раскрытия, восстановления или создания дубля по тому же номеру. |
| 14 | Пользователь не имеет права на клиента. | Демо | «Нет разрешения»; данные карточки не рендерятся, сохранение контекста запрещено. Защищённый пример не создаёт клиента в общем списке. |
| 15 | Клиент находится в чужом агентском пространстве. | Модель | Сопоставление и связь ограничены scope; чужая карточка не предлагается. Реальный tenant/ACL проверяется будущим сервером, локальная роль не является авторизацией. |
| 16 | Общая линия одновременно вызывает несколько агентов. | Демо + контракт | Общая линия, отдельный ответственный по звонку. Несколько legs должны сводиться адаптером к одному ID разговора; реального провайдера нет. |
| 17 | На звонок ответил другой сотрудник. | Демо/тест | Отдельный статус «Ответил коллега», без личного пропущенного и повторного callback. Поздний missed-leg не открывает вызов заново. |
| 18 | Вызов перенаправлен. | Дизайн-контракт | Переадресация сама не равна ответу. Адаптер сохраняет canonical ID и назначение; неизвестный итог остаётся unknown. Transfer API отсутствует. |
| 19 | Вызов отменён звонящим. | Демо | Отдельный статус отмены звонящим. Не утверждать разговор; ручной результат и задача сохраняются отдельно. |
| 20 | Звонок отклонён. | Демо | Отдельный статус отклонения, отличный от missed. Ручной результат не меняет состояние провайдера. |
| 21 | Звонок пропущен. | Демо | Перезвонить / напомнить / не требует ответа. Намерение набора не закрывает обращение; для закрытия нужен отдельный сохранённый результат. |
| 22 | Звонок завершился до загрузки контекста. | Демо | Loading/error контекста независим от статуса звонка. Можно завершить событие и затем загрузить CRM, без выдуманного разговора. |
| 23 | Пользователь открыл CRM во время активного разговора. | Демо | Доступный контекст и переход Client 360°. В режиме событий АТС нет кнопок управления вызовом; только VoIP-симуляция показывает команды. |
| 24 | Пользователь открыл системный набор номера, но не позвонил. | Демо | Кнопка сообщает о намерении набора; реальный dialer не открывается. Нет провайдерского ответа и автоматического «Связались». |
| 25 | Звонок есть в АТС, но событие пришло с задержкой. | Демо | Раздельно исходное время и получение, предупреждение о задержке. Сохраняется тот же ID; получение не заменяет начало звонка. |
| 26 | Webhook пришёл повторно. | Модель/тест | Одинаковый provider+externalId+sequence не меняет данные и историю. Дубликат заявки/задачи не создаётся. |
| 27 | Отдельные состояния вызова пришли не по порядку. | Модель/тест | Старые sequence отклоняются; завершённый вызов не возвращается в ringing. Сервер должен обеспечить сравнимый порядок событий. |
| 28 | Провайдер не предоставляет длительность. | Демо | Поле длительности отсутствует, источник это поясняет. Длительность не вычисляется из времени получения и не подменяется нулём. |
| 29 | Провайдер не предоставляет причину завершения. | Модель | Причина завершения не выводится, если её нет. Статус failed/unknown не превращается в пользовательский бизнес-исход. |
| 30 | Система не знает, был ли разговор. | Демо | «Уточните результат звонка». Известен только технический unknown; ручная отметка подписана пользователем, ответ АТС не придумывается. |
| 31 | Пользователь отказал в разрешении Caller ID. | Концепт | Caller ID выключен, доступна ручная CRM и другие способы подключения. Реальные разрешения и их изменение в вебе отсутствуют. |
| 32 | На iOS Call Directory не включён. | Концепт | iPhone: подпись определения выключена; Call Directory объяснён отдельно. Системные настройки не открываются и не меняются. |
| 33 | На iOS справочник определения устарел. | Концепт | Вариант «Справочник обновляется» объясняет, что системная подпись может быть прежней. Ложного мгновенного обновления нет. |
| 34 | Live Caller ID Lookup не настроен или не прошёл необходимые процедуры. | Концепт | Live Lookup обозначен отдельной нативной/серверной зависимостью. Неподключённая функция не создаёт подтверждённого CRM-события. |
| 35 | Android не получил роль call-screening. | Концепт | Android требует поддерживаемую роль. Без неё остаются ручная CRM и событие рабочей АТС, если оно действительно получено. |
| 36 | Android ограничивает предусмотренный UI. | Концепт | Веб не рисует произвольный overlay поверх SIM-вызова. Нужна проверка допустимых системных поверхностей на конкретном Android/OEM. |
| 37 | Устройство заблокировано. | Демо + native gap | Переключатель блокировки скрывает номер, имя, запрос и заметку текущего рабочего вызова. Системный пример независим и явно иллюстративен; реальная блокировка ОС не тестировалась. |
| 38 | Уведомления SuperApp отключены. | Дизайн-контракт | Без уведомлений не обещать показ. При открытии приложения доступные серверные события должны появляться в Inbox; push-система отсутствует. |
| 39 | Приложение было закрыто во время звонка. | Граница демо | Перезагрузка/закрытие сеанса очищает память и черновики, о чём сказано в интерфейсе. Для восстановления нужен сервер; фоновые SIM-события не выдумываются. |
| 40 | Веб-клиент открыт в фоновой вкладке. | Дизайн-контракт | Не перехватывать фокус фоновой вкладки. Этот прототип открывается явно; реальная доставка событий/уведомлений в фоне не подключена. |
| 41 | Интернет отсутствует. | Демо | Offline помечен, поля остаются в памяти, сохранение отключено. После восстановления повтор выполняется явно; статуса «синхронизировано» нет. |
| 42 | Прервалось соединение с АТС. | Демо | Показано последнее время получения и потеря телефонии. Контекст остаётся с предупреждением, управление VoIP скрыто; новые состояния не подтверждены. |
| 43 | Клиент говорит по другому каналу. | Дизайн-контракт | Другой канал не доказывает ответ на звонок. Сохранить пользовательскую заметку отдельно; объединение потоков каналов требует сервера. |
| 44 | Пользователь уже зафиксировал результат на втором устройстве. | Демо | Симуляция другого устройства меняет бизнес-версию; чужой результат сохраняется, собственный черновик можно добавить отдельной заметкой. |
| 45 | Два сотрудника пытаются записать разные результаты. | Модель + контракт | Старая версия не перезаписывает результат. Локально проверено reducer-тестом; реальная конкурентность сотрудников требует серверной транзакции. |
| 46 | Пользователь закрыл окно фиксации без сохранения. | Демо | Закрытие/Escape → продолжить либо закрыть с черновиком. По ID звонка ввод восстанавливается до перезагрузки. |
| 47 | Пользователь создал задачу и потерял интернет. | Демо + контракт | Результат и задача локально атомарны. Offline до подтверждения не сохраняет их; сетевой сбой после серверного commit требует idempotency/status API. |
| 48 | Пользователь сохранил заметку дважды. | Модель/тест | Повтор operationId заметки отклонён. При сохранении форма заблокирована; две разные осознанные заметки не считаются одним действием. |
| 49 | Контакт удалён или объединён после звонка. | Дизайн-контракт | Если доступной карточки нет, её детали не показывать; merge должен вернуть canonical clientId. CRUD удаления/слияния и архивный журнал сервера не реализованы. |
| 50 | У клиента указан запрет на рекламные сообщения. | Граница | Номер не означает согласие на маркетинг. Отправки нет; реальные consent-флаги и канальная блокировка — зависимость CRM/провайдера. |
| 51 | У клиента нет подтверждённого активного запроса. | Демо-модель | Пустой запрос показывается нейтрально, без бюджета и района. Новый контакт допускает «Пока неизвестно»; ручное редактирование через Client 360°. |

## Контракт аналитики для следующего этапа

Сейчас аналитическая отправка отсутствует. Имена событий из брифа сохраняются как контракт. Поля: eventName, локальный/серверный correlationId, scopeKind, providerKind, platformKind, technicalStatus, sourceKind, resultCode, durationBucket, capabilityState. Не отправлять имя, телефон, текст заметки/запроса, адрес и бюджет. Дедупликацию, задержку и повтор связывать с техническим callId на сервере с контролем доступа.

| Группа | События | Когда допустимо |
|---|---|---|
| Определение | caller_id_context_requested / available, caller_id_match_found / ambiguous / no_match | Отдельно запрос, доступный контекст и совпадение; совпадение не равно личности |
| Доступность | caller_id_permission_disabled, caller_id_settings_opened | Реальное состояние/действие native; не из простого переключателя демо |
| Провайдер | business_call_event_received / answered / missed / ended | Только подтверждённый источник, не SIM-догадка и не ручной результат |
| Форма | post_call_sheet_viewed, post_call_outcome_selected / saved / save_failed | Просмотр/намерение/подтверждённый commit различать |
| Связанные действия | post_call_followup_created, post_call_client_created / opened | После реального успешного изменения/перехода, без счёта повторов |
| Callback | post_call_callback_started / confirmed | started — намерение; confirmed — допустимый источник ответа, не открытие dialer |
| Качество событий | call_event_deduplicated, call_event_delayed | Повтор/задержка одного канонического вызова, без новой заявки |

KPI считаются только на поддерживаемых подтверждённых рабочих событиях: доля допустимых совпадений, доля полезного контекста, доля сохранённых post-call результатов и доля подтверждённых восстановленных пропущенных. Ручной исход нужно выделять в отдельный источник; демо не включать в продуктовые метрики.
