# №08 — Caller ID и следующий шаг после звонка

Дата: 27 октября 2026 года. Источник — актуальный пользовательский `docs/prompt/8.md` (44 раздела, 60 edge cases, 50 критериев приёмки). Пользователь отдельно выбрал продолжение веб-прототипа; это заменяет ограничение «без кода» в брифе. Файл из основной рабочей папки скопирован в текущую рабочую копию; оригинал не менялся.

## Решение UX

Ценность: узнать разрешённый контекст и сохранить следующий шаг без длинной анкеты. Основной путь веб-версии — контекст события рабочей телефонии и Post-Call. iOS/Android System Caller ID и управляемый VoIP представлены отдельными обозначенными концептами; они не становятся интеграциями от переключения вкладки.

Главная мобильная композиция: статус и источник → имя/неоднозначное совпадение → номер → один запрос, последнее взаимодействие и ближайшая задача → одно основное действие. На этапе после звонка основной блок — результат, необязательная заметка и следующий контакт. При пропущенном вызове первично «Перезвонить»; открытие набора не закрывает событие.

Варианты рассматривались: постоянная модалка на любом событии, отдельный телефонный раздел и локальное рабочее пространство по явному открытию. Выбран последний: он сохраняет контекст Today/Inbox/Client 360° и не имитирует перехват системного вызова.

## Токены и компоненты

- Основа `#FFFFFF`; текст/CTA `#000000`; текст CTA `#FFFFFF`.
- Вторичный текст `#6B6B6B` (контраст на светло-серых поверхностях); поверхность `#F7F7F7`; граница `#E8E8E8`.
- Системный шрифт существующего прототипа; имя 30 px, заголовок карточки 18 px, текст 15–16 px, метаданные 12–13 px, CTA 16 px.
- Поля 20–24 px; сетка 8 px; радиусы карточек 20 px; группировка по смыслу, без одинаковой обводки вокруг каждой строки.
- Выравнивание контекста по левому краю; имя и действия входящего звонка образуют спокойный центр. Зоны действия от 44×44 px.
- Минимальные переходы после действия пользователя; Reduce Motion отключает движение. Звонок не ждёт загрузки контекста или анимации.

Это намеренно продолжает бело-чёрный стиль SuperApp. Акцент — читаемая идентичность и следующий шаг, без декоративной пульсации, рейтинга сделки или AI-прогнозов.

## Достоверность и модель

Техническое состояние вызова, результат пользователя и задача — отдельные сущности. Один `provider + externalCallId` соответствует одному вызову; последовательные обновления меняют его, повтор и устаревшая версия не создают новую заявку. Новый вызов с того же номера — отдельное событие. Время начала, получения и сохранения хранятся раздельно; длительность показывается только из события.

Сохранение результата атомарно меняет локальную запись, историю, очередь Today/Inbox и при необходимости создаёт одну задачу с датой и связью. Операция имеет стабильный ID, а бизнес-версия защищает от молчаливого перезаписывания. Технический «пропущен» не превращается в «разговор состоялся» после ручной отметки обратного контакта.

Известный номер — совпадение с доступной карточкой, не удостоверение личности. При нескольких совпадениях сначала нейтральный выбор; запросы и заметки до выбора скрыты. Новый контакт создаётся только явно. Номер не означает согласия на маркетинг. Скрытый/некорректный номер не даёт действия обратного вызова. Архив, отсутствие прав, заблокированный экран и удалённая карточка не раскрывают кэшированный чужой контекст.

Черновик сохраняется в памяти сеанса по ID вызова. При выходе с изменениями предлагается вернуться либо закрыть с черновиком. Ошибка и offline сохраняют поля; фиктивного состояния «синхронизировано» нет. Перезагрузка очищает демо-сеанс, что обозначается явно.

## Границы платформ

| Режим | Поверхность и доступное действие | Граница прототипа |
|---|---|---|
| iOS Call Directory | Системная идентификация из справочника расширения | Минимальный системный концепт без CRM-полей и произвольных кнопок |
| iOS Live Caller ID Lookup | Расширение и серверная инфраструктура с процедурами Apple | Отдельный концепт доступности/настройки |
| Android | Поддерживаемая роль call-screening и системная поверхность | Концепт с выключенной/запрещённой функцией; без запроса прав |
| АТС: события | Контекст, история, результат, задача | Основной локальный демо-путь; кнопок управления реальным звонком нет |
| Управляемый VoIP | Команды и события допустимого телефонного клиента | Обозначенная симуляция; нет микрофона, звонков, записи или передачи аудио |
| SIM без нативной функции | Ручная CRM и пояснение доступных способов | Не создаёт автоматическое событие звонка |

Платформенные ограничения сверены с первичными источниками: [Apple Call Directory](https://developer.apple.com/documentation/callkit/cxcalldirectoryprovider), [Apple Live Caller ID Lookup](https://developer.apple.com/documentation/identitylookup/getting-up-to-date-calling-and-blocking-information-for-your-app), [Android CallScreeningService](https://developer.android.com/reference/android/telecom/CallScreeningService). Apple описывает отдельное расширение и серверную инфраструктуру Live Lookup; Android требует соответствующую роль и ответ сервиса в пределах пяти секунд. Эти механизмы не реализуются Next.js-страницей.

## Проверка

Сквозные пути: известный/неизвестный/неоднозначный/скрытый номер; звонок собственника; входящий/активный/завершённый/пропущенный/отклонённый/отменённый/принятый коллегой/неизвестный исход; дата без длительности; задержка/повтор/перестановка событий; ошибка CRM и сохранения; offline; ограничения контекста и блокировка; создание клиента, связывание, задача и возвраты. Отдельно — 320/393/430/1024, крупный текст, клавиатура и фокус.

Полный реестр 60 случаев и приёмка оформляются в handoff после реализации. Реальный VoiceOver/TalkBack, системные разрешения и телефонные интеграции не подменяются браузерной проверкой. Figma-файл в этом этапе не создаётся: выбран исполняемый веб-прототип и локальная спецификация.
