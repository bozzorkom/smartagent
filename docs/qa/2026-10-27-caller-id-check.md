27 октября 2026. Рабочая копия: `/Users/shohsanam/.codex/worktrees/client-360-qa/smartagent`, ветка `codex/client-360-qa`, база `8d37b2b`. Пользователь выбрал интерактивный веб-прототип вместо Figma. Проверка: реальный браузер `http://localhost:3000/`; все телефоны, имена, события и записи — явно вымышленные примеры.

## Результат

Локальная цепочка «событие звонка → контекст → ручной результат/задача → Today, Inbox и Client 360°» работает. Проверены основной поток, пропущенный звонок, создание/связь клиента, вложенные возвраты, командное назначение, повтор/устаревшее событие, ошибки и сохранение черновика. Это не проверка телефонного провайдера или нативного Caller ID.

## Воспроизведённые проблемы и исправления

| Проблема до исправления | Исправление / подтверждение |
|---|---|
| Во время сохранения можно было менять заметку; позднее изменение пропадало | Fieldset блокирует поля и демо-переключатели на время операции. Проверено фактическое disabled-состояние во время 450 ms ожидания. |
| Закрытый пример добавлял приватного клиента в общий список | Restricted-пример больше не seed-ит CRM. В чистом сеансе Caller и список клиентов не раскрыли имя/запрос. |
| Уточнение номера оставляло прежнюю связь с клиентом | Identity review снимает прежнюю идентичность, блокирует итог до явного выбора. Четыре регрессионных случая модели проверяют корректировку/архив/неизвестный статус; UI повторно проверен. |
| Вложенный переход A → Client → B → Client терял возврат к A | Стек возвратов хранит ID, прокрутку и исходный Client-frame. Полный вложенный путь пройден в браузере, вернулся исходный ID. |
| После одной только связи возникал ложный незавершённый ввод | Выбор контакта очищается после подтверждения; чистая форма закрывается без предупреждения. |
| При создании нового клиента показывались две одинаковые основные кнопки | Начальная кнопка скрыта в открытой форме; в ней одна «Создать клиента». |
| Поздний missed-leg открывал общий вызов, уже принятый коллегой | Regression сначала упал; reducer теперь отклоняет такую смену, 44/44 теста зелёные. |
| Крупный текст не увеличивал новый Caller-раздел | Веб-пример увеличивает основной текст/поля до 18 px, метаданные до 16 px; 320×568 без горизонтального overflow. |
| Создание задачи попадало в блок последней CRM-записи вместо взаимодействия | История задач исключена из краткого последнего взаимодействия. Входящий показывает ручную договорённость и следующий шаг раздельно. |
| Общая линия не включала командные записи без старого sample-дня; журнал их скрывал | Готовность командного демо учитывает записи вызовов. Назначение и результат отображены в командном журнале. |
| Безответственный звонок не учитывался в сводке распределения | Воспроизведено: одна запись, счётчик 0. Исправлено: счётчик 1 → «Распределить» → «Назначить по звонку» → Азиз → счётчик 0; обращение остаётся открытым. |
| Фокус терялся после замены формы результатом | После успешного сохранения `activeElement.id = caller-result-title`; диалог сохраняет клавиатурный контекст. |

## Размеры, визуальная проверка, доступность

| Размер | Горизонтальное переполнение страницы / диалога | Кнопки Caller меньше 44×44 CSS px |
|---|---|---|
| 320×568 | 0 / 0 | Нет |
| 393×852 | 0 / 0 | Нет |
| 430×932 | 0 / 0 | Нет |
| 1024×768 | 0 / 0 | Нет |

Веб-режим крупного текста проверен отдельно на 320×568: основной текст и поле заметки — 18 px, переполнение — 0. Радиокарточки переходят в один столбец. Проверены семантика полей/групп/диалога, видимый фокус, уведомления об ошибках и результате. Вторичный текст нового раздела затемнён до #6B6B6B для читаемости на серых поверхностях. Reduce Motion задан в CSS. Реальные VoiceOver/TalkBack, нативный Dynamic Type, экранная клавиатура и системный Caller ID на iOS/Android не проверены.

## Полнота и границы

[Передача №08](../design/08-caller-id/handoff.md) отдельно сопоставляет **все 60 edge cases и 50 критериев** с работающим демо, концептом или зависимостью. Доступны 22 интерактивных примера. Figma не создавалась по подтверждённому пользователем выбору веб-формата.

Реальные серверные права, телефония, микрофон, запись, маркетинговое согласие, фоновые события, push, долговременное хранение и синхронизация устройств отсутствуют. Нативные API, правила магазина и поведение конкретного провайдера должны пройти отдельную техническую оценку. В прототипе нет автоматической отправки или обещания синхронизации. Все новые данные и черновики живут в памяти сеанса.

Существующие исправления Client 360° сохранены в этой же рабочей копии. Коммит и публикация текущего этапа не выполнялись; пользовательскую основную рабочую папку этот этап не изменял.
